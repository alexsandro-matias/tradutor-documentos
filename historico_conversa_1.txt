3. ATUALIZACAO PARA SUPORTE A .TXT E .DOCX
============================================================

Usuario pediu para atualizar o README de acordo com as funcionalidades de
traducao .docx e .txt e forneceu uma proposta sugerida por outra IA.

Foram verificados os arquivos e implementacao atuais. Confirmado no codigo:
- O endpoint POST /traduzir aceita .txt e .docx.
- A traducao padrao e de ingles (en) para portugues (pb).
- O backend extrai paragrafos, traduz cada paragrafo e gera um arquivo binario.
- A resposta de sucesso nao e JSON: e o proprio arquivo traduzido, com headers
  Content-Type e Content-Disposition.
- Os erros HTTP continuam sendo retornados como JSON.
- O frontend faz upload e baixa o Blob recebido do servidor.
- Existem os modulos tradutor/leitor_arquivo.py e
  tradutor/gerador_arquivo.py.
- A dependencia python-docx consta em requirements.txt.
- O sentencizer local usa expressoes regulares para evitar downloads de modelos
  auxiliares Stanza/SpaCy.

O arquivo .README foi atualizado para incluir:
- Fluxo e funcionalidades de traducao .txt e .docx;
- Instalacao no Windows, Linux e macOS;
- Configuracao ARGOS_CHUNK_TYPE e ARGOS_DEBUG;
- Detalhes do endpoint com resposta binaria e exemplos de curl;
- Estrutura atual de arquivos;
- Limitacoes dos documentos .docx;
- Troubleshooting de certificado corporativo/Netskope e codificacao UTF-8;
- Roadmap.

Limitacoes documentadas:
- .doc e outros formatos nao sao suportados; apenas .txt e .docx.
- Arquivos .txt devem usar UTF-8.
- O leitor de .docx extrai paragrafos e a geracao cria novo documento apenas
  com os paragrafos traduzidos; a formatacao avancada, tabelas, imagens e
  outros elementos nao sao preservados.
- Arquivos grandes podem consumir memoria/tempo; o tamanho nao esta limitado
  explicitamente.

OBSERVACAO:
O arquivo de documentacao chama-se literalmente ".README" (com ponto inicial),
nao README.md.

5. COMO EXECUTAR O PROJETO FASTAPI
============================================================

Usuario perguntou como executar o projeto.

Com ambiente virtual existente, no PowerShell:

  cd C:\Users\PB7P\projeto-traducao
  .\.venv\Scripts\Activate.ps1
  python -m uvicorn app:app --reload

Depois, abrir:

  http://127.0.0.1:8000

Para parar o servidor: Ctrl+C.

Se .venv nao existir, recriar e instalar dependencias:

  cd C:\Users\PB7P\projeto-traducao
  py -m venv .venv
  .\.venv\Scripts\Activate.ps1
  python -m pip install --upgrade pip
  python -m pip install -r requirements.txt
  python -m uvicorn app:app --reload

A primeira inicializacao pode tentar baixar o modelo de traducao Argos caso ele
nao esteja instalado localmente.
